## Что работает сейчас

- Приложение запускает HTTP-сервер на `:8080` или на адресе из `HTTP_ADDR`.
- `GET /health` возвращает `200 OK` и JSON `{"status":"ok"}`.
- `GET /ready` возвращает `200 OK`, когда PostgreSQL доступен, или `503`, когда он недоступен.
- При запуске приложение подключается к базе и применяет ещё не выполненные миграции.
- API авторизации работает через серверную сессию в `HttpOnly` cookie.
- При `SIGINT` или `SIGTERM` сервер получает до 10 секунд на корректное завершение запросов.
- Для PostgreSQL используется `github.com/jackc/pgx/v5` версии 5.10.0.
- Для Argon2id используется `golang.org/x/crypto` версии 0.56.0.

Сборка, тесты, авторизация и запуск с PostgreSQL 18.6 проверены 2026-09-05.

## Известные проблемы

- `api/v1/ui/analytics.go` содержит только пустую функцию с временным именем `asfdf`.
- В рабочей папке находится неотслеживаемый временный файл `.DS_Store.swp`.
- Реализованные миграции пока запускаются самим приложением; для нескольких production-реплик позднее может потребоваться отдельная команда миграции.
- Для production ещё не настроены TLS, сервисный менеджер, резервные копии и CI/CD.
- Ограничение частоты запросов хранится в памяти одного процесса; для нескольких реплик потребуется общий limiter или ограничение на reverse proxy.

## Важные технические детали

- Планируемая основа: Go, TypeScript и PostgreSQL.
- HTTP-сервер пока использует только стандартную библиотеку Go.
- Адрес сервера задаётся через `HTTP_ADDR`; значение по умолчанию — `:8080`.
- `DATABASE_URL` обязателен и не должен попадать в логи.
- Идентификаторы основных сущностей имеют тип UUID и будут создаваться приложением.
- Временные ряды на первом этапе хранятся в PostgreSQL.
- Python рассматривается только как возможный будущий сервис расширенной аналитики.
- Метрики сервера невозможно получить браузерным трекером: для них нужен отдельный агент.

## Что важно помнить

- README сейчас является описанием желаемого продукта, а не перечнем реализованных возможностей.
- Для MVP приняты email/пароль, серверная cookie-сессия и один владелец сайта.
- `SESSION_COOKIE_SECURE` должен оставаться `true` на HTTPS-сервере; `false` разрешён только для локального HTTP.
- Изменения схемы базы данных после её появления должны выполняться миграциями.
- Секреты нельзя добавлять в репозиторий; они должны храниться в локальном `.env`.
